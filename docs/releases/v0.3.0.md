**CORS Unblocker 0.3.0** is about being easier to use. The popup now tells you what's wrong with the page and offers one next step; the DevTools panel and Settings are simpler; and the toolbar icon shows at a glance whether overrides are on. Nothing about how rules behave has changed, so there is no migration.

> This remains a **development tool**: keep it switched off (or paused) when you're not debugging.

## Highlights

### A popup with one next step
The popup shows a single card for the current tab, with exactly one main button for its state:

- **Calls are blocked** → **Fix 3 calls**. "What will change" lists the settings it will change before you click.
- **Calls were just fixed** → **Reload page** to retry them.
- **The page isn't trusted** → **Trust localhost:3000**.
- **Overrides are paused** → **Resume now**.

Sites read the way people say them (`localhost:3000`, not `http://localhost:3000/*`). Risky or rarely used actions, such as overriding a server's own CORS headers or no longer trusting a page, are quiet links, and the override still asks you to confirm. Every state fits within Chrome's 600px popup height.

### Pause for an hour
**Pause 1 hour** switches overrides off and back on by themselves. That works even if the browser is restarted or the extension's background worker is asleep when the hour ends.

### See the state from the toolbar
The icon is full colour while overrides are on and greyed out while they're off or paused. Its tooltip spells it out, for example "CORS Unblocker: On · 2 trusted pages". The red badge still counts blocked calls on the current tab.

### A simpler DevTools panel
- Opens on **Requests** when calls on the page are blocked, with the blocked calls first.
- The header is down to one row: name, status, **Settings** and an on/off switch labelled with its state.
- Mode, theme, header options and default methods now live only in Settings.
- Works in narrow DevTools docks without clipping.

### Settings built around your rules
- **One list** of trusted pages, domain rules (which Settings didn't show before) and skip rules. Each shows the site in plain words, the exact pattern beneath, and labels for its type and options.
- **Per-rule options:** methods and "Any site may read" are tucked into each rule's **Options**, so the page opens with 2 checkboxes instead of 72.
- **One form** adds a page as **Trust** or **Skip**.
- **Everything else** sits below the rules: behavior, blocked-call detection, response headers and methods, appearance, import/export, and reset.

### First run and branding
- New installs open Settings with a short **welcome**: trust your page, what the red number means, and how to fix it.
- The **new CORS Unblocker logo** appears in the popup, DevTools panel and Settings, with light and dark versions that follow your theme. The extension's display name is now "CORS Unblocker".

### Accessibility
An automated check with axe-core now passes on every page, in light and dark themes. Light-theme accent text was darkened to meet contrast minimums, a label in the dark theme was fixed, and heading order was corrected.

## Changes to know about
- **Mode and theme** moved from the popup to Settings. In global mode, the popup shows a warning with a one-click way back to trusted pages only.
- **New `alarms` permission** for Pause. Browsers grant it without a prompt.
- Releases are now built and published by a GitHub workflow that re-runs every check on the tagged commit, and each release includes a `SHA256SUMS.txt` file.

## Testing and known limitations
- **Chrome** is tested end to end. 25 tests load the built extension into Chromium and make real cross-origin calls: trusted pages, skip rules, preflights, credentials, exposed headers, blocked-call detection and fixes, pause and resume, the toolbar state, and the welcome. CI runs them alongside 89 unit tests.
- **Firefox** passes Mozilla's add-on linter with no warnings, but its end-to-end suite isn't written yet. Please report anything that behaves differently from Chrome.
- **Not yet tested in a real browser:** the popup, DevTools panel and Settings layouts were checked with simulated extension data in a browser, not inside a running extension's popup or DevTools.
