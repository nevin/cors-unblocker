**CORS Unblocker 1.1** lets IT administrators manage the extension through browser policy, so it can be approved for company machines. Nothing changes for anyone without a policy, and your rules and settings carry over unchanged.

## New in 1.1

### Settings your organization can enforce
Administrators can set three keys through Chrome, Edge or Firefox enterprise policy:

| Key | Effect |
|---|---|
| `disableOverrides` | Keeps CORS overrides off; users can't switch them on. Blocked calls are still detected and explained, so developers know to fix the server. |
| `trustedPages` | Pages trusted for every user, such as `localhost:3000`. Users can add their own pages but can't edit or remove these. |
| `blockEveryWebsiteMode` | Removes "Every website" mode, so only trusted pages and individually unblocked calls get relaxed CORS. |

- **Clear for users.**
  - Settings opens with one line saying what your organization manages.
  - Pages the organization trusts are marked "Set by your organization" and can't be edited, moved or removed.
  - Locked switches are disabled, with the reason on hover.
  - With overrides kept off, blocked calls are still listed. The popup and DevTools panel explain they can only be fixed on the server, and offer no Fix or Trust buttons that couldn't work.
- **Never mixed into your own settings.** The policy is applied on top of your own rules and is never saved with them. If the policy is removed, everything goes back to your own choices.
- **Validated by Chrome.** The Chrome build declares the keys in `policy-schema.json`, so `chrome://policy` checks them and shows them.

### Admin guide
[docs/enterprise-policy.md](https://github.com/nevin/cors-unblocker/blob/v1.1.0/docs/enterprise-policy.md) has ready-to-use examples for:
- Windows registry and Group Policy (Chrome, Edge, Firefox);
- macOS configuration profiles;
- Linux policy files;
- the Google Admin console;
- Firefox's `policies.json`.

### Tested with real policy
Six new end-to-end tests in each browser set a real policy through the browser's own policy engine:
- Firefox through `policies.json`;
- Chrome through its Linux policy folder, on CI.

They check that a page the policy trusts works with no rules of the user's own, that "Every website" mode is ignored, and that with overrides kept off no headers change while blocked calls are still counted. 65 end-to-end tests now run in real Chrome and Firefox on every change and before every release, alongside 108 unit tests.

## Privacy
The [privacy policy](https://github.com/nevin/cors-unblocker/blob/v1.1.0/PRIVACY.md) now says the extension reads any settings your organization sets through browser policy. It only reads them, and sends nothing anywhere.

## Upgrading
Nothing to do. Without a policy, 1.1 behaves exactly like 1.0.
